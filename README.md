# Онлайн-бронирование мест в кинотеатре

Учебный проект по дисциплине «Технологии веб-программирования».


## Стек
- Frontend: React (JavaScript), Vite
- Backend: Python, FastAPI
- БД: PostgreSQL

## Структура
- `backend/` — серверная часть
- `frontend/` — клиентская часть
- `docs/` — диаграммы, схема БД, проектное задание

## Команда
- Гребенюк Дмитрий — backend
- Соколова Екатерина — frontend

## Правила работы с Git
- В `main` напрямую не коммитим, только через Pull Request.
- Одна задача — одна ветка: `feature/...`, `fix/...`, `docs/...`, `chore/...`.
- Перед началом работы: `git switch main`, `git pull`, затем новая ветка.
- Сообщения коммитов с префиксом: `feat:`, `fix:`, `docs:`, `chore:`.
- Файл `.env` с паролями не коммитим.

## Запуск

### Что нужно установить
- Python 3.10+ (проверено на 3.14) с python.org
- PostgreSQL 13+ (проверено на 18)
- Node.js и npm для запуска интерфейса

### База данных
1. В pgAdmin создать базу `Cinema`.
2. Выполнить в ней скрипт `docs/cinema_schema.sql` — создаёт таблицы, индексы и триггеры
   (Query Tool → открыть файл → Execute).
   Внимание: скрипт начинается с `DROP`, при повторном запуске всё удаляется.
3. Выполнить `docs/seed.sql` — заполняет базу тестовыми данными: 3 зала, 182 места,
   23 фильма и 98 сеансов на 7 дней от даты запуска, пользователи и примеры броней.
   Можно запускать повторно перед демонстрацией, чтобы обновить даты сеансов.
   Внимание: скрипт очищает все данные, включая созданных вручную пользователей и брони.

#### Обновление существующей базы

В pgAdmin открой **Cinema → Query Tool**. Для существующей базы выполни недостающие миграции по порядку. Каждая применяется один раз.

| Если в базе отсутствует столбец | Скрипт | Что получат существующие записи |
| --- | --- | --- |
| `bookings.ticket_code` | [001_add_booking_ticket_code.sql](docs/migrations/001_add_booking_ticket_code.sql) | Уникальный код билета для каждой брони |
| `screenings.price` | [002_add_screening_price.sql](docs/migrations/002_add_screening_price.sql) | Сеансы и старые брони получат учебную цену 350 ₽ за место |

Проверить наличие столбцов можно в pgAdmin в разделе **Tables → имя таблицы → Columns**. При создании новой базы из актуального `cinema_schema.sql` все изменения уже входят в схему.

### Backend
Команды для PowerShell, из корня репозитория:

```powershell
cd backend
py -m venv venv                       # создать виртуальное окружение
.\venv\Scripts\Activate.ps1           # активировать (в начале строки появится (venv))
pip install -r requirements.txt       # установить зависимости
if (!(Test-Path .env)) { Copy-Item .env.example .env }
```

Открыть `backend/.env` и указать свой пароль от PostgreSQL в `DB_PASSWORD`.
Также заменить заглушку `JWT_SECRET` своим случайным секретом для подписи токенов.
Сгенерировать его можно из активированного виртуального окружения:

```powershell
python -c "import secrets; print(secrets.token_hex(32))"
```

Полученное значение записать в `JWT_SECRET` в `.env`. Этот файл не добавлять в Git.
Токен входа действует 8 часов; после изменения секрета ранее выданные токены станут недействительными.

Запуск сервера:

```powershell
python -m uvicorn app.main:app --reload
```

Проверка:
- http://127.0.0.1:8000/health — ответ `{"status": "ok"}`
- http://127.0.0.1:8000/docs — документация API (Swagger)

Если активация выдаёт ошибку «выполнение сценариев отключено», один раз выполнить:
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`

### Frontend

Оставь терминал с FastAPI открытым. Во втором терминале PowerShell из корня репозитория выполни:

```powershell
cd frontend
npm ci
npm run dev
```

Открой адрес, который напечатает Vite (обычно http://localhost:5173). В версии интерфейса с интеграцией из `feature/booking-ui` запросы идут на `/api`: Vite передаёт `/api/movies` в FastAPI как `/movies` на порту 8000. В Swagger используй пути без `/api`.

## API для интерфейса

| Экран | Метод и путь FastAPI | Данные |
| --- | --- | --- |
| Баннер и каталог | **GET** `/movies` | Все фильмы. Необязательные фильтры `date=YYYY-MM-DD` и `genre`. С датой возвращаются только фильмы с будущим сеансом в этот день, по одной карточке на фильм |
| Выбор сеанса | **GET** `/screenings?movie_id=…&date=…` | Время, зал и `price` за одно место |
| Схема зала | **GET** `/screenings/{id}/seats` | `id`, ряд, место и `is_occupied` |
| Оформление | **POST** `/bookings` | Передай `screening_id` и массив `seat_ids`. При успехе — `201`, код билета и стоимость. При `409` обнови схему мест |
| Личный кабинет | **GET** `/bookings`, **PATCH** `/bookings/{id}/cancel` | Своя история и отмена активной брони до начала. Для QR используй строку `ticket_code` |
| Брони администратора | **GET** `/admin/bookings`, **PATCH** `/admin/bookings/{id}/status` | Все зрители, места и статусы. Фильтр `?status=active`. Тело изменения — `{"status":"cancelled"}` или `{"status":"completed"}` |
| Проверка QR | **GET** `/admin/tickets/{ticket_code}` | Карточка с актуальным статусом. Отменённый билет сохраняет код и возвращается со статусом `cancelled` |
| Каталог и залы | **GET**, **POST** `/admin/movies`, `/admin/halls`. **GET**, **PUT**, **DELETE** по `/{id}` | Для обновления фильма передай всю карточку. Для создания зала — `name`, `rows`, `seats_per_row`. Для переименования достаточно `name` |
| Расписание и заполняемость | **GET**, **POST** `/admin/screenings`. **PATCH**, **DELETE** `/admin/screenings/{id}` | Список принимает `date`, `movie_id`, `hall_id`. Ответ содержит `total_seats` и `occupied_seats`. Занятость учитывает места активных и завершённых броней |

- После **POST** `/auth/login` передавай токен в заголовке `Authorization: Bearer <access_token>`. В Swagger нажми **Authorize** и вставь токен. Для маршрутов `/admin` нужна роль `admin`. Без входа сервер отвечает `401`, зрителю на административном маршруте — `403`.
- Для нового сеанса передай, например, `{"movie_id":1,"hall_id":1,"starts_at":"2030-04-15T18:00:00","price":450}`. Выбери свободное время в будущем по местным часам кинотеатра. Сервер вычисляет конец по длительности фильма. Два сеанса в зале могут идти вплотную. При переносе меняются время и/или цена, фильм и зал сохраняются.
- Цена — целое число рублей за место. При оформлении PostgreSQL записывает её в `price_per_seat`, а API считает `total_price` по числу мест. Новая цена сеанса действует для следующих броней.
- Администратор может отменить активную бронь до начала сеанса и завершить её после окончания. История и код билета сохраняются. Сеанс с бронями защищён от удаления, а зал с расписанием сохраняет схему мест.

### Проверка перед демонстрацией

1. В Swagger войди как администратор и создай будущий сеанс. Используй `movie_id` и `hall_id` из списков админки.
2. Войди как зритель, найди этот сеанс по дате, выбери свободное место и оформи бронь. Сверь `id`, `ticket_code` и `total_price` в ответе `201` и в личном кабинете.
3. Под администратором найди тот же `id` в **GET** `/admin/bookings`, отмени бронь. Под зрителем проверь `cancelled` в истории и `is_occupied: false` у освободившегося места.

Автоматическая проверка проходит через HTTP и PostgreSQL. Запусти её из `backend` с настроенным `.env`. Тестовый пользователь БД должен иметь право создавать схемы. Тесты создают и удаляют собственные временные схемы с демонстрационными данными.

```powershell
.\venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
```
